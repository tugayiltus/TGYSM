# TGYSM frontend — agent guidance

Rules for UI code in `frontend/` (ADR-0027). They adapt the Astryx repository's `AGENTS.md` and `npx astryx docs principles` to this app. The Astryx block below is generated by `npx astryx init`; do not edit it by hand.

## Before you write UI code

- On each new branch, run the bootstrap once: `npx astryx docs principles --dense`, `npx astryx docs tokens --dense`, `npx astryx docs theme --dense`, `npx astryx component --list`, `npx astryx template --list`. The docs match the installed version, not your memory.
- Before you use or change a component, run `npx astryx component <Name> --dense`. Do not invent props.
- For a large doc, run `npx astryx docs <topic> --index`, then read one section.
- After a `@astryxdesign/*` version bump, run `npx astryx upgrade --from <old version> --apply`, then all gates.

## Building screens

- Build outside-in: shell and region budgets first, then content (`npx astryx docs layout`). Start a new page from `npx astryx template <id>`.
- Use Astryx components for every visible or interactive pattern. Keep a raw element only when its native semantics are necessary (`<form>`) or Astryx has no equivalent.
  - Layout `div`: `VStack`, `HStack`, `Grid`, `Card`, `Section`, `Center`.
  - `span`, `p`, `h1`–`h6`: `Text`, `Heading`.
  - `button`, linked action: `Button`, `IconButton`, `Link`.
  - In-page `nav`, `aside`: `LayoutPanel`. `header`, `main`: `LayoutHeader`, `LayoutContent` inside `Layout`.
- Dense data goes in rows (`Table`, `List`/`Item`), never in Card-wrapped lists. `Card` is for widgets, galleries and settings groups.
- Every table that lists records has filters: a toolbar above it for search and the main filters (pattern: `npx astryx template table-filter`), with the filter state in the URL query so a link reopens the same view.
- `Badge` shows counts only. Status uses `StatusDot` or `Token`.
- Icons render through `Icon`, `IconButton` or a component's icon prop, with values from `Icons` in `src/shared/ui/icons.ts`. Never render a raw SVG or a Lucide component directly.
- Links go through `Link` or `useLinkComponent()`; `LinkProvider` routes them through React Router. No hard-coded `<a>`.
- Form inputs are controlled. With react-hook-form, use the bound fields in `src/shared/form/`.
- Styling order: component props, then tokens (`var(--color-*)`, `var(--spacing-*)`, `var(--radius-*)`). No inline styles on raw elements, no hex colors, no px spacing, no new `.css`/`.scss`, no Tailwind, no StyleX compiler. Colors and palettes change only through the theme, never `:root`.
- Charts take colors from data tokens (`npx astryx docs tokens/tokens-data`), not fixed colors.

## Design rules

Adapted from the Astryx design records (`docs/design/` in `meta/astryx`). Astryx components already own press, hover, motion, reduced-motion and right-to-left behaviour; do not rebuild them.

- **Page composition:** one page title, one control region, one primary content region. One primary action per action group; other actions are secondary or ghost; destructive actions stay clearly separate. On narrow screens the reading order stays: context, primary content, supporting content, actions. Keyboard and touch reach every action without hover.
- **Spacing:** three gap tiers. Smallest between a label and its value or control, larger between fields or peers, largest between sections. Use space and alignment to group before you add a `Card` or border. Do not use one gap everywhere.
- **Controls in a row** (toolbar, filter bar) use one size, so they share one height and baseline.
- **Typography:** pick `Heading`/`Text` by role (page heading, section heading, body, label, supporting text, code), never by the size that fits. Hierarchy never depends on color alone. Long text keeps a readable line length.
- **Color:** use semantic tokens and component variants. Supporting text must not look disabled. No status meaning by color alone.
- **System states:**
  - Loading: a `Skeleton` shaped like the coming content, so nothing jumps. A busy action keeps its size (`isLoading` on the `Button`).
  - Status pairs color with an icon or text. In-flow, lasting messages use a quiet `Banner`. Short-lived feedback uses a toast. Urgent errors that need a decision use `AlertDialog`.
  - Disabled controls stay readable and, when useful, say why (`disabledMessage`, tooltip).
  - A message stays next to the thing it describes, also at phone width.
- **Elevation and shape:** do not add shadows, borders or radii to Astryx surfaces. A surface uses one edge style (border or shadow, not both). No thick side stripes as accents. Floating content (menus, popovers) uses Astryx layers, so it is never clipped.
- **Icons:** each icon has a purpose; no decoration. Same concept, same icon across the app (`Icons` map). Outlined artwork; filled only for an on/selected state or status. Size by role: `xsm` indicator, `sm` standard control, `md` prominent control, `lg` display. Icon color uses roles (`primary`, `secondary`, `success`, `warning`, `error`, `inherit`). An icon that does something sits in `IconButton`/`Button` with an accessible name; never put a click handler on a bare `Icon`.
- **Motion:** no custom animations or transitions. Keep the default hover delays of `Tooltip`, `HoverCard` and menus.
- **Direction:** the app is Turkish, left to right. Still use start/end props, never left/right, so layout stays direction-neutral.

## Comments and docs (ASD-STE100 style)

- Names, structure and control flow explain the code. A comment explains only what the code cannot show: a reason, a constraint, an invariant, or a browser quirk.
- Never narrate the code or restate a name or a type. Never cite a pull request, an issue or a date. Cite an ADR as `(ADR-NNNN)` only where that decision applies.
- Write comments in Simplified Technical English: at most 20 words in an instruction, 25 in a description. One topic per sentence, active voice, present tense, simple words with one meaning, no filler.
- A file created or rewritten in the migration starts with a short header (about 12 lines at most): `@input` (what it takes), `@output` (what it renders or returns), `@position` (where it sits in the app). Keep the header true when the file changes.
- Keep JSDoc on exported components, props, hooks and utilities. `@example` fences are plain ```` ``` ````, never ```` ```tsx ````.
- Every `useEffect` has one line that names the external system it synchronizes.

## Checking your work

- Gates: `tools/lint.sh` (ESLint, TypeScript, `npx astryx doctor --built .`), `tools/test.sh`.
- Before you call a screen done, review it with `npx astryx docs is-my-code-good`: app fit, Astryx components, icons, styling, layout, assets, code health. Check light and dark mode and phone width in the browser.
