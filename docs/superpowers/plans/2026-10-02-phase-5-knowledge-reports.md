# Phase 5 Knowledge Base and Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. **Ruling (plan format, carried over from Phase 2–4, owner-approved):** tasks list files, interfaces and tests instead of full inline code; code is written once, under TDD, from the spec. Each task: write the listed failing tests, watch them fail, implement, run the task command, record the result.

**Goal:** Deliver Phase 5 — knowledge base with revisions and visibility, all reports with filters, drill-down and Excel export (sync and background) — per spec §6–§9.

**Architecture:** Knowledge base is a new `Knowledge` area (Domain entity + revisions, Application handlers, `/kb` endpoints) with one visibility rule shared by list, search, get and ticket links. Reports live in `Application/Reports`: one `ReportFilter` + `ReportScope` produce a base query; each report is a set of named metrics, and every metric exposes one predicate reused by figure, drill-down and export, so the three always agree. Large exports run as `export_jobs` in the existing Worker; files go through `IFileStore`.

**Tech Stack:** .NET 10, EF Core + Npgsql, PostgreSQL 17 (`pg_trgm`), ClosedXML, React 19 + TanStack Query, `react-markdown` (no `rehype-raw`), Recharts, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-27-phase-4-5-sla-email-knowledge-reports-design.md` (§1, §6, §7, Phase 5 parts of §8–§10); requirements `tgysm.md` §4, §11, §12, §20 items 5, 13, 14.

## Global Constraints

- All Phase 1–4 constraints apply (English code/URLs/DB, Turkish UI via i18n, zero warnings, no lint disables, no magic literals, `tools/` scripts, TDD, no push, stage named paths only, no AI attribution).
- Backend tests: `dotnet test --solution backend/Tgysm.slnx` (MTP); filters `--filter-class` / `--filter-method`. Integration tests on real PostgreSQL 17.
- New error codes → `ErrorCodes` + `errors.json`; audit actions → `AuditActions` + `admin.json` `auditActions`; entity types → `AuditEntityTypes` + `entityTypes` (enforced by `TranslationCoverageTests`).
- Time only through `TimeProvider`; tests use `FakeTimeProvider`.
- Every state change: domain method → handler writes entity + revision/history + audit in one `SaveChanges`; `xmin` concurrency on `knowledge_articles` and `export_jobs`.
- Search keys only through `TurkishText.ToSearchKey`; trigram indexes through `TrigramIndex` constants.
- Article limits: title ≤ 200, summary ≤ 500, body ≤ 50,000 (named constants in `ArticleLimits`).
- Export: sync limit 5,000 rows (`ReportExportLimits.SyncMaxRows`); file lifetime 24 h (`ReportExportLimits.FileLifetime`).
- Ageing buckets: 0–1, 2–3, 4–7, 8+ days (`ReportBuckets.AgeingDays`).
- Every ratio returns numerator and denominator; zero denominator → `value = null`, UI shows "Veri yok".
- Report scope: admin all tickets; IT staff tickets whose current `team_id` is in their teams (not tickets they only requested); employees 403. Asset/warranty reports: IT staff and admins, all assets.
- Department filter = requester's `department_id`; location filter = ticket `location_id`.
- Frontend: new routes lazy-loaded; chunks `vendor-charts` (recharts, d3-*), `vendor-markdown` (react-markdown, remark-*, micromark, mdast-*, unist-*, hast-*), `feature-kb`, `feature-reports` added to `vite.config.ts`.
- After API changes: `tools/gen-api-types.sh`.

## Review Focus

1. Employee reaches an internal or draft article by guessing its id, through search text matching the internal body, through a ticket's article list, or through a public reply that embeds `/kb/{id}` — always 404 / filtered / `knowledge.internal_article_in_public_reply` (Tasks 3, 4).
2. IT staff moved out of a team after starting a background export, or deactivated — download returns 404; their figures never include tickets of other teams, including through `assigneeId`/`teamId` filters pointing at foreign teams (Tasks 6, 12).
3. Same filters give figure count = drill-down total = export row count for every metric, including ratios whose denominator excludes cancelled/rejected tickets (Tasks 7–11).
4. Turkish search: "IŞIK", "ışık", "isik" variants and "Outlook" vs "outlook" find the same article; a search of only punctuation/whitespace returns the normal list, not an error (Task 3).
5. Article edited by two IT users at once — second save 409 with no lost revision; restoring an archived article returns it to draft and never republishes silently (Tasks 2, 3).
